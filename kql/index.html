High KDL-0002 Sentinel

Password spray from a single IP address

Flags an IP address that produced invalid-password failures (50126) against many distinct accounts within a short window. Spraying tries one or two common passwords across many users to stay under per-account lockout thresholds, so the signal is breadth (distinct users), not depth (attempts per user). Any successful sign-in from the same IP in the window is surfaced alongside, since that is the account that needs an immediate password reset.

Credential AccessT1110.003

Tables: SigninLogs  ·  Runs: every 1h, looking back 1h

Query 
let minDistinctUsers = 10;
let window = 1h;
let failures = SigninLogs
| where TimeGenerated > ago(window)
| where ResultType == "50126"
| summarize FailedUsers = dcount(UserPrincipalName), Attempts = count(),
    SampleUsers = make_set(UserPrincipalName, 25), FirstSeen = min(TimeGenerated),
    LastSeen = max(TimeGenerated), UserAgents = make_set(UserAgent, 5)
    by IPAddress
| where FailedUsers >= minDistinctUsers;
let successes = SigninLogs
| where TimeGenerated > ago(window)
| where ResultType == "0"
| summarize CompromisedCandidates = make_set(UserPrincipalName, 25) by IPAddress;
failures
| join kind=leftouter successes on IPAddress
| project-away IPAddress1
| extend CompromisedCandidates = coalesce(CompromisedCandidates, dynamic([]))
| order by FailedUsers desc
False positives & tuning
  • A shared egress IP (VPN concentrator, campus NAT) after a mass password change.
  • Misconfigured app or script retrying with a stale credential across many accounts.
  • Lower minDistinctUsers for small tenants (under 200 users), raise it for large shared NAT ranges.
  • Exclude corporate egress IPs via a watchlist only after confirming the source.
References
  • https://learn.microsoft.com/security/operations/incident-response-playbook-password-spray
High KDL-0003 Sentinel

MFA fatigue - repeated MFA denials followed by success

Detects a user who denied or failed several MFA prompts (500121) and then completed a successful sign-in shortly after. This is the push-bombing pattern where an attacker holding a valid password spams approvals until the user accepts one. Number matching reduces but does not eliminate this risk.

Credential AccessT1621

Tables: SigninLogs  ·  Runs: every 1h, looking back 2h

Query 
let minDenials = 3;
let window = 2h;
let denials = SigninLogs
| where TimeGenerated > ago(window)
| where ResultType == "500121"
| summarize Denials = count(), FirstDenial = min(TimeGenerated), LastDenial = max(TimeGenerated),
    DenialIPs = make_set(IPAddress, 10) by UserPrincipalName
| where Denials >= minDenials;
SigninLogs
| where TimeGenerated > ago(window)
| where ResultType == "0" and AuthenticationRequirement == "multiFactorAuthentication"
| project SuccessTime = TimeGenerated, UserPrincipalName, SuccessIP = IPAddress, AppDisplayName,
    Country = tostring(LocationDetails.countryOrRegion)
| join kind=inner denials on UserPrincipalName
| where SuccessTime between (FirstDenial .. (LastDenial + 30m))
| summarize arg_min(SuccessTime, *) by UserPrincipalName
| project UserPrincipalName, Denials, FirstDenial, LastDenial, SuccessTime, SuccessIP, DenialIPs, AppDisplayName, Country
False positives & tuning
  • User repeatedly mistyping the number-match code on a new phone.
  • Raise minDenials if helpdesk sees frequent fat-finger denials; correlate with "user reported suspicious activity" events.
References
  • https://attack.mitre.org/techniques/T1621/
High KDL-0005 Sentinel

Break-glass (emergency access) account sign-in

Any sign-in attempt, successful or failed, by an emergency access account. These accounts are excluded from Conditional Access by design and should almost never be used, so every event deserves a human looking at it.

Initial AccessPrivilege EscalationT1078.004

Tables: SigninLogs, AADNonInteractiveUserSignInLogs  ·  Runs: every 15m, looking back 15m

Query 
// Replace with your emergency access UPNs, or use: _GetWatchlist('BreakGlassAccounts') | project SearchKey
let breakGlass = dynamic(["breakglass01@contoso.onmicrosoft.com", "breakglass02@contoso.onmicrosoft.com"]);
union isfuzzy=true SigninLogs, AADNonInteractiveUserSignInLogs
| where TimeGenerated > ago(15m)
| where UserPrincipalName in~ (breakGlass)
// LocationDetails is dynamic in SigninLogs but string in the non-interactive table, so use Location.
| project TimeGenerated, UserPrincipalName, ResultType, ResultDescription, IPAddress, Country = Location,
    AppDisplayName, ClientAppUsed, UserAgent, Type
False positives & tuning
  • Scheduled break-glass validation tests (document them and close with that reason).
  • Keep this rule at 15 minutes; route to on-call, not the normal queue.
References

High KDL-0007 Sentinel

Privileged Entra role assigned outside PIM

Detects a direct (permanent, active) assignment to a privileged Entra ID role that did not go through Privileged Identity Management. In a tenant that uses PIM for just-in-time access, direct assignments bypass approval, justification and expiry and are a classic persistence move after an admin account is compromised.

PersistencePrivilege EscalationT1098.003

Tables: AuditLogs  ·  Runs: every 1h, looking back 1h

Query 
let privilegedRoles = dynamic(["Global Administrator", "Privileged Role Administrator",
    "Privileged Authentication Administrator", "Security Administrator", "Exchange Administrator",
    "SharePoint Administrator", "User Administrator", "Application Administrator",
    "Cloud Application Administrator", "Conditional Access Administrator", "Intune Administrator",
    "Authentication Administrator", "Hybrid Identity Administrator"]);
AuditLogs
| where TimeGenerated > ago(1h)
| where OperationName == "Add member to role"
| where LoggedByService != "PIM"
| extend Actor = coalesce(tostring(InitiatedBy.user.userPrincipalName), tostring(InitiatedBy.app.displayName))
| extend ActorIP = tostring(InitiatedBy.user.ipAddress)
| extend Target = tostring(TargetResources[0].userPrincipalName)
| mv-apply prop = TargetResources[0].modifiedProperties on (
    where tostring(prop.displayName) == "Role.DisplayName"
    | extend RoleName = trim(@'"', tostring(prop.newValue))
  )
| where RoleName in~ (privilegedRoles)
| project TimeGenerated, Actor, ActorIP, Target, RoleName, Result, CorrelationId
False positives & tuning
  • Initial tenant build-out or an approved break-glass recovery.
  • If you do not use PIM yet, this fires for every role change; that is the point - make it a change-control check.
References
  • https://learn.microsoft.com/entra/id-governance/privileged-identity-management/pim-configure
High KDL-0010 Sentinel

New MFA method registered from an IP the user has not signed in from

After phishing a password or session, attackers register their own authenticator app or phone number to survive a password reset. This correlates security-info registration events with the user's 14-day sign-in IP history and flags registrations from an unfamiliar address.

PersistenceT1098.005

Tables: AuditLogs, SigninLogs  ·  Runs: every 1h, looking back 14d

Query 
let lookback = 14d;
let recent = 1h;
let knownIPs = SigninLogs
| where TimeGenerated between (ago(lookback) .. ago(recent))
| where ResultType == "0"
| summarize KnownIPs = make_set(IPAddress, 200) by UserPrincipalName;
AuditLogs
| where TimeGenerated > ago(recent)
| where LoggedByService == "Authentication Methods"
| where OperationName in ("User registered security info", "User changed default security info",
    "Admin registered security info")
| extend UserPrincipalName = tostring(TargetResources[0].userPrincipalName)
| extend RegistrationIP = tostring(InitiatedBy.user.ipAddress)
| join kind=leftouter knownIPs on UserPrincipalName
| where isempty(RegistrationIP) == false and not(set_has_element(coalesce(KnownIPs, dynamic([])), RegistrationIP))
| project TimeGenerated, UserPrincipalName, OperationName, ResultReason, RegistrationIP
False positives & tuning
  • New phone setup from home on a residential IP never used before.
  • Restrict security-info registration to trusted locations with a CA policy on "Register security information".
References
  • https://learn.microsoft.com/entra/identity/conditional-access/how-to-policy-registration
High KDL-0011 Sentinel

OAuth consent granted with high-risk permissions

Illicit consent grants give an attacker-controlled app durable, MFA-proof access to mail and files. This flags user or admin consents that include high-risk delegated or application permissions such as Mail.Read, Mail.Send, Files.ReadWrite.All or offline_access combined with mailbox scopes.

Credential AccessPersistenceT1528

Tables: AuditLogs  ·  Runs: every 1h, looking back 1h

Query 
let riskyScopes = dynamic(["Mail.Read", "Mail.ReadWrite", "Mail.Send", "MailboxSettings.ReadWrite",
    "Files.Read.All", "Files.ReadWrite.All", "Sites.ReadWrite.All", "Directory.ReadWrite.All",
    "User.ReadWrite.All", "Application.ReadWrite.All", "full_access_as_app", "EWS.AccessAsUser.All"]);
AuditLogs
| where TimeGenerated > ago(1h)
| where OperationName == "Consent to application"
| extend Actor = tostring(InitiatedBy.user.userPrincipalName), ActorIP = tostring(InitiatedBy.user.ipAddress)
| extend AppName = tostring(TargetResources[0].displayName), AppId = tostring(TargetResources[0].id)
| mv-apply prop = TargetResources[0].modifiedProperties on (
    where tostring(prop.displayName) in ("ConsentAction.Permissions", "ConsentContext.IsAdminConsent")
    | summarize Props = make_bag(bag_pack(tostring(prop.displayName), tostring(prop.newValue)))
  )
| extend Permissions = tostring(Props["ConsentAction.Permissions"]), IsAdminConsent = tostring(Props["ConsentContext.IsAdminConsent"])
| extend MatchedScopes = set_intersect(extract_all(@"([A-Za-z_]+\.[A-Za-z.]+|full_access_as_app)", Permissions), riskyScopes)
| where array_length(MatchedScopes) > 0
| project TimeGenerated, Actor, ActorIP, AppName, AppId, IsAdminConsent, MatchedScopes, Permissions
False positives & tuning
  • Legitimate admin-approved integrations (backup, e-signature, CRM mail sync).
  • Disable user consent or restrict to verified publishers + low-risk scopes; this rule then catches admin consents only.
References
  • https://learn.microsoft.com/security/operations/incident-response-playbook-app-consent
High KDL-0013 Sentinel

Domain federation or authentication settings changed

Converting a managed domain to federated, or changing the signing certificate or issuer of an existing federation, lets an attacker mint tokens for any user in that domain (Golden SAML / "domain trust modification"). These operations are rare enough that every event should be reviewed.

Privilege EscalationDefense EvasionT1484.002

Tables: AuditLogs  ·  Runs: every 1h, looking back 1h

Query 
AuditLogs
| where TimeGenerated > ago(1h)
| where OperationName in ("Set federation settings on domain", "Set domain authentication",
    "Add unverified domain", "Verify domain", "Add verified domain")
| extend Actor = coalesce(tostring(InitiatedBy.user.userPrincipalName), tostring(InitiatedBy.app.displayName))
| extend ActorIP = tostring(InitiatedBy.user.ipAddress)
| extend Domain = tostring(TargetResources[0].displayName)
| extend Changes = TargetResources[0].modifiedProperties
| project TimeGenerated, OperationName, Domain, Actor, ActorIP, Result, Changes
False positives & tuning
  • Planned identity-provider migrations (e.g. AD FS to cloud auth) - tie to a change ticket.
  • Do not tune out; route straight to the identity owner.
References
  • https://attack.mitre.org/techniques/T1484/002/
High KDL-0015 Sentinel

Suspicious inbox rule created (BEC pattern)

Business email compromise actors create inbox rules that hide replies from the real user: delete or move messages to obscure folders (RSS Feeds, Conversation History, Archive) when they contain words like invoice, payment, wire or the name of the victim's finance contact. This flags new or modified rules with those traits.

Defense EvasionCollectionT1564.008

Tables: OfficeActivity  ·  Runs: every 1h, looking back 1h

Query 
let keywords = dynamic(["invoice", "payment", "wire", "transfer", "bank", "remittance", "ach",
    "urgent", "w2", "payroll", "deposit", "hacked", "phish", "suspicious", "fraud"]);
let hiddenFolders = dynamic(["RSS Feeds", "RSS Subscriptions", "Conversation History", "Archive", "Junk Email", "Deleted Items"]);
OfficeActivity
| where TimeGenerated > ago(1h)
| where Operation in ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules")
| extend Params = parse_json(Parameters)
| mv-apply p = Params on (
    summarize RuleParams = make_bag(bag_pack(tostring(p.Name), tostring(p.Value)))
  )
| extend RuleName = tostring(RuleParams.Name),
    DeletesMail = tostring(RuleParams.DeleteMessage) =~ "True" or tostring(RuleParams.SoftDeleteMessage) =~ "True",
    MarksRead = tostring(RuleParams.MarkAsRead) =~ "True",
    MoveTo = tostring(RuleParams.MoveToFolder),
    ForwardTo = strcat(tostring(RuleParams.ForwardTo), tostring(RuleParams.RedirectTo), tostring(RuleParams.ForwardAsAttachmentTo)),
    Words = tolower(strcat(tostring(RuleParams.SubjectContainsWords), " ", tostring(RuleParams.SubjectOrBodyContainsWords), " ", tostring(RuleParams.BodyContainsWords)))
| extend KeywordHit = Words has_any (keywords),
    HiddenFolder = MoveTo has_any (hiddenFolders),
    ShortName = strlen(RuleName) <= 2 or RuleName matches regex @"^[\.\s,;]+$"
| extend Score = toint(DeletesMail) * 2 + toint(MarksRead) + toint(HiddenFolder) * 2 + toint(KeywordHit) * 2
    + toint(isnotempty(ForwardTo)) * 3 + toint(ShortName)
| where Score >= 3
| project TimeGenerated, UserId, ClientIP, Operation, RuleName, Score, DeletesMail, MarksRead, MoveTo, ForwardTo, Words
| order by Score desc
False positives & tuning
  • Users filing vendor invoices into an "Archive" folder with mark-as-read.
  • Raise the Score threshold to 4 if your users heavily automate mailbox filing.
  • Pair with MailboxThreatHunter for a tenant-wide sweep of existing rules (this rule only sees new changes).
References
  • https://learn.microsoft.com/security/operations/incident-response-playbook-compromised-malicious-app
High KDL-0016 Sentinel

Mailbox forwarding to an external address configured

Detects Set-Mailbox changes that add SMTP forwarding (ForwardingSmtpAddress or ForwardingAddress) to a domain outside the organization. Mailbox-level forwarding is invisible to the user in Outlook and silently copies every message out.

CollectionExfiltrationT1114.003

Tables: OfficeActivity  ·  Runs: every 1h, looking back 1h

Query 
// List your accepted domains so internal forwarding is not flagged.
let internalDomains = dynamic(["contoso.com", "contoso.onmicrosoft.com"]);
OfficeActivity
| where TimeGenerated > ago(1h)
| where Operation in ("Set-Mailbox", "New-TransportRule", "Set-TransportRule")
| extend Params = parse_json(Parameters)
| mv-apply p = Params on (
    summarize P = make_bag(bag_pack(tostring(p.Name), tostring(p.Value)))
  )
| extend ForwardTo = tostring(coalesce(P.ForwardingSmtpAddress, P.ForwardingAddress,
    P.RedirectMessageTo, P.BlindCopyTo, P.CopyTo))
| where isnotempty(ForwardTo)
| extend ForwardDomain = tolower(extract(@"@([A-Za-z0-9\.\-]+)", 1, ForwardTo))
| where isnotempty(ForwardDomain) and not(ForwardDomain in (internalDomains))
| extend DeliverToMailboxAndForward = tostring(P.DeliverToMailboxAndForward)
| project TimeGenerated, Operation, Actor = UserId, ClientIP, Target = OfficeObjectId,
    ForwardTo, ForwardDomain, DeliverToMailboxAndForward
False positives & tuning
  • Executives forwarding to an approved personal assistant service; mergers with not-yet-accepted domains.
  • Block automatic external forwarding with the outbound spam policy; this rule then catches policy bypass attempts.
References
  • https://learn.microsoft.com/defender-office-365/outbound-spam-policies-external-email-forwarding
High KDL-0018 DefenderXDR · Sentinel

User clicked a link in an email later removed by ZAP

Zero-hour auto purge (ZAP) removes phishing that was only identified after delivery. ZAP cleans the mailbox but cannot undo a click that already happened. This joins post-delivery ZAP actions with Safe Links click events so the SOC can reset credentials for the users who actually clicked.

Initial AccessT1566.002

Tables: EmailPostDeliveryEvents, UrlClickEvents, EmailEvents  ·  Runs: every 1h, looking back 1d

Query 
let lookback = 1d;
let zapped = EmailPostDeliveryEvents
| where Timestamp > ago(lookback)
| where ActionType in ("Phish ZAP", "Malware ZAP")
| project ZapTime = Timestamp, NetworkMessageId, ZapAction = ActionType, RecipientEmailAddress;
UrlClickEvents
| where Timestamp > ago(lookback)
| where ActionType in ("ClickAllowed", "UrlScanInProgress") or IsClickedThrough == true
| project ClickTime = Timestamp, NetworkMessageId, AccountUpn, Url, ClickAction = ActionType, IPAddress
| join kind=inner zapped on NetworkMessageId
| where ClickTime <= ZapTime
| join kind=leftouter (EmailEvents | where Timestamp > ago(lookback)
    | project NetworkMessageId, Subject, SenderFromAddress, SenderIPv4) on NetworkMessageId
| project ClickTime, ZapTime, AccountUpn, Url, ClickAction, ZapAction, Subject, SenderFromAddress, SenderIPv4, IPAddress
False positives & tuning
  • Rare; ZAP false positives on legitimate bulk mail occasionally occur.
  • Feed results into an automated "revoke sessions + require password change" playbook.

High KDL-0021 DefenderXDR · Sentinel

Shadow copy or backup catalog deletion (pre-ransomware)

Ransomware operators delete Volume Shadow Copies, the Windows backup catalog and disable recovery mode right before encryption so victims cannot roll back. These commands almost never run legitimately on endpoints and should trigger isolation.

ImpactT1490

Tables: DeviceProcessEvents  ·  Runs: every 15m, looking back 15m

Query 
DeviceProcessEvents
| where Timestamp > ago(15m)
| where (FileName =~ "vssadmin.exe" and ProcessCommandLine has_all ("delete", "shadows"))
    or (FileName =~ "vssadmin.exe" and ProcessCommandLine has_all ("resize", "shadowstorage"))
    or (FileName =~ "wmic.exe" and ProcessCommandLine has_all ("shadowcopy", "delete"))
    or (FileName =~ "wbadmin.exe" and ProcessCommandLine has_any ("delete catalog", "delete systemstatebackup"))
    or (FileName =~ "bcdedit.exe" and ProcessCommandLine has_any ("recoveryenabled no", "bootstatuspolicy ignoreallfailures"))
    or (FileName in~ ("powershell.exe", "pwsh.exe") and ProcessCommandLine has "Win32_ShadowCopy" and ProcessCommandLine has_any ("Delete", "Remove-"))
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine,
    InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessSHA256
False positives & tuning
  • Backup software resizing shadow storage (validate the parent process and signer).
  • Wire to an automated device isolation response; minutes matter here.
References
  • https://attack.mitre.org/techniques/T1490/
High KDL-0022 DefenderXDR · Sentinel

LSASS memory dump via comsvcs.dll or procdump

Dumping LSASS memory yields cached credentials and Kerberos tickets. Common living-off-the-land variants call comsvcs.dll MiniDump through rundll32 or use Sysinternals procdump against lsass. Credential Guard and ASR rules mitigate this; the detection catches attempts on machines where they are not yet enforced.

Credential AccessT1003.001

Tables: DeviceProcessEvents  ·  Runs: every 15m, looking back 15m

Query 
DeviceProcessEvents
| where Timestamp > ago(15m)
| where (FileName =~ "rundll32.exe" and ProcessCommandLine has "comsvcs" and ProcessCommandLine has_any ("MiniDump", "#24", "#+24"))
    or (FileName in~ ("procdump.exe", "procdump64.exe") and ProcessCommandLine has "lsass")
    or (ProcessCommandLine has "lsass" and ProcessCommandLine has_any ("sekurlsa", "minidump", ".dmp") and FileName !in~ ("MsMpEng.exe", "WerFault.exe"))
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine,
    InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessIntegrityLevel
False positives & tuning
  • Authorized troubleshooting dumps by Microsoft support or an IR team (should be ticketed).
  • Enable the ASR rule "Block credential stealing from the Windows local security authority subsystem".
References
  • https://attack.mitre.org/techniques/T1003/001/
High KDL-0024 DefenderXDR · Sentinel

Inbound RDP accepted from a public IP address

Internet-exposed RDP is one of the most common ransomware entry points. This flags devices that accepted inbound RDP (TCP 3389) from a public IP, which means a firewall or NAT rule is exposing the host directly.

Initial AccessLateral MovementT1133T1021.001

Query 
DeviceNetworkEvents
| where Timestamp > ago(1h)
| where ActionType == "InboundConnectionAccepted"
| where LocalPort == 3389
| where RemoteIPType == "Public"
| summarize Connections = count(), RemoteIPs = make_set(RemoteIP, 50), FirstSeen = min(Timestamp),
    LastSeen = max(Timestamp) by DeviceName, LocalIP
| order by Connections desc
False positives & tuning
  • Hosts behind an RD Gateway that is itself logging the public client IP (verify topology).
  • The fix is the firewall rule, not the detection - move access behind VPN or RD Gateway with MFA.
References
  • https://attack.mitre.org/techniques/T1133/

Word, Excel, PowerPoint or Outlook launching cmd, PowerShell, wscript, mshta or rundll32 is the textbook macro / malicious-attachment execution chain. ASR rules can block this; the detection covers audit-mode devices and gaps.

Medium KDL-0001 Sentinel

Successful sign-in using legacy authentication

Detects successful Entra ID sign-ins that used a legacy authentication protocol (IMAP, POP3, SMTP AUTH, ActiveSync, EWS basic, etc.). Legacy protocols cannot enforce MFA, so a successful legacy sign-in is a common foothold for password spray and credential stuffing. In a tenant that has blocked legacy auth with Conditional Access, any hit is either a policy gap or a misconfigured exclusion.

Initial AccessDefense EvasionT1078.004

Tables: SigninLogs  ·  Runs: every 1h, looking back 1h

Query 
let modernClients = dynamic(["Browser", "Mobile Apps and Desktop clients"]);
SigninLogs
| where TimeGenerated > ago(1h)
| where ResultType == "0"
| where isnotempty(ClientAppUsed) and ClientAppUsed !in (modernClients)
| extend Country = tostring(LocationDetails.countryOrRegion)
| summarize SignIns = count(), Apps = make_set(AppDisplayName, 10),
    Protocols = make_set(ClientAppUsed, 10), IPs = make_set(IPAddress, 20),
    Countries = make_set(Country, 10), FirstSeen = min(TimeGenerated), LastSeen = max(TimeGenerated)
    by UserPrincipalName
| order by SignIns desc
False positives & tuning
  • Multifunction printers / scanners using SMTP AUTH for scan-to-email.
  • Line-of-business apps still using EWS basic auth or IMAP service accounts.
  • Move known service accounts to a watchlist and exclude them explicitly, then fix them.
  • Pair with a Conditional Access policy that blocks "Other clients" and "Exchange ActiveSync clients".
References
  • https://learn.microsoft.com/entra/identity/conditional-access/policy-block-legacy-authentication
Medium KDL-0004 Sentinel

Successful sign-in from a country not seen for the user in 14 days

Builds a 14-day per-user country baseline from successful sign-ins and alerts when a user successfully signs in from a country outside that baseline. Simple, explainable and hard to evade without a residential proxy in the right country.

Initial AccessT1078.004

Tables: SigninLogs  ·  Runs: every 1h, looking back 14d

Query 
let lookback = 14d;
let recent = 1h;
let baseline = SigninLogs
| where TimeGenerated between (ago(lookback) .. ago(recent))
| where ResultType == "0"
| extend Country = tostring(LocationDetails.countryOrRegion)
| where isnotempty(Country)
| summarize KnownCountries = make_set(Country, 50) by UserPrincipalName;
SigninLogs
| where TimeGenerated > ago(recent)
| where ResultType == "0"
| extend Country = tostring(LocationDetails.countryOrRegion), City = tostring(LocationDetails.city)
| where isnotempty(Country)
| join kind=inner baseline on UserPrincipalName
| where not(set_has_element(KnownCountries, Country))
| summarize FirstSeen = min(TimeGenerated), IPs = make_set(IPAddress, 10), Apps = make_set(AppDisplayName, 10)
    by UserPrincipalName, Country, City, Baseline = tostring(KnownCountries)
False positives & tuning
  • Business travel; staff using a personal VPN or a mobile carrier that geolocates abroad.
  • Users with no baseline (new hires) are excluded by the inner join on purpose; cover them with a separate new-user rule.
References
  • https://learn.microsoft.com/entra/identity/monitoring-health/concept-sign-ins

| summarize SignIns = count(), Apps = make_set(AppDisplayName), IPs = make_set(IPAddress, 10),
    Countries = make_set(Country), LastSeen = max(TimeGenerated) by UserPrincipalName

  • Break-glass accounts (covered separately by KDL-0005).

Medium KDL-0020 DefenderXDR · Sentinel

PowerShell launched with an encoded command

-EncodedCommand hides the real script from casual inspection and is heavily used by malware loaders. The query decodes the Base64 (UTF-16LE) payload inline so the analyst sees the actual script without leaving the results grid.

Tables: DeviceProcessEvents  ·  Runs: every 1h, looking back 1h

Query 
DeviceProcessEvents
| where Timestamp > ago(1h)
| where FileName in~ ("powershell.exe", "pwsh.exe", "powershell_ise.exe")
| where ProcessCommandLine matches regex @"(?i)\s-(e|ec|en|enc|enco|encodedcommand)\s+[A-Za-z0-9+/=]{20,}"
| extend Encoded = extract(@"(?i)\s-(?:e|ec|en|enc|enco|encodedcommand)\s+([A-Za-z0-9+/=]{20,})", 1, ProcessCommandLine)
// -EncodedCommand is UTF-16LE: decode, then strip the interleaved NUL bytes.
| extend Decoded = replace_regex(base64_decode_tostring(Encoded), @"\x00", "")
| extend Suspicious = Decoded has_any ("IEX", "Invoke-Expression", "DownloadString", "FromBase64String",
    "Net.WebClient", "AmsiUtils", "-bxor", "Reflection.Assembly")
| project Timestamp, DeviceName, AccountName, Suspicious, Decoded, ProcessCommandLine,
    InitiatingProcessFileName, InitiatingProcessCommandLine
| order by Suspicious desc, Timestamp desc
False positives & tuning
  • Some management agents (SCCM/Intune remediation, RMM tools) use -EncodedCommand legitimately.
  • Baseline by InitiatingProcessFileName for a week, then exclude known agents.
